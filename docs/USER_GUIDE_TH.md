# คู่มือใช้งาน FPL Decision Lab

## ระบบนี้ช่วยอะไร

FPL Decision Lab รวมข้อมูล FPL, โปรแกรมแข่ง, คะแนนคาดการณ์ และกติกาการจัดทีมไว้
ในหน้าเดียว เป้าหมายคือช่วยลดการตัดสินใจจากอารมณ์ โดยยังให้คุณเป็นคนกด transfer
และยืนยันทีมในเว็บ FPL เองเสมอ

ระบบออนไลน์พร้อมใช้งานแล้วที่:

**[https://sarayutp.github.io/fpl-decision-lab/](https://sarayutp.github.io/fpl-decision-lab/)**

นี่คือวิธีใช้งานหลัก ไม่ต้องเปิด MacBook ทิ้งไว้ ไม่ต้องเปิด Terminal และไม่ต้องติดตั้ง
Python ระบบทำงานเป็น static PWA บน GitHub Pages ส่วน GitHub Actions ทำ data
pipeline และ deploy ให้ตามเวลา

## เริ่มใช้งานผ่านเว็บ

1. เปิด Dashboard จาก URL ด้านบนด้วย Chrome, Safari หรือ Browser บนมือถือ
2. ตรวจกล่อง `Team Source of Truth` ว่าเป็น `Sarayut FC` และ Team ID `5105794`
3. ตรวจป้ายความสดของข้อมูลด้านขวาบน
4. อ่านคำตอบ 5 ช่องใน `This Gameweek`: Transfer, Starting XI, Captain/Vice,
   Bench และ Chip
5. เปิด `News & Risk` ตรวจสถานะ FPL และเพิ่มข่าวใหม่ที่มีลิงก์/เวลา หากมี
6. เปิด `Transfers` แล้วกรอก Free Transfer กับราคาขายจริงของผู้เล่นที่อยู่ในแผน
7. กด `ดูเหตุผล` เพื่อแยกข้อเท็จจริง ค่าประมาณ และข้อจำกัด
8. ก่อน deadline ใช้ส่วน `AI Briefing` เพื่อตรวจข่าวกับ ChatGPT Plus
9. กลับไปยืนยัน transfer, XI, bench และ captain ในเว็บ FPL ด้วยตัวเอง

ถ้า Team ID ที่ตั้งใจดูไม่ตรงกับ snapshot เว็บจะหยุด captain, optimizer, swap,
Squad Lab และ AI briefing โดยอัตโนมัติ ให้แก้ Team ID หรือ refresh pipeline ด้วยทีมที่
ถูกต้องก่อน ระบบจะไม่ใช้คำแนะนำจากคนละทีมต่อไป

Chrome จะแสดงปุ่มติดตั้ง `FPL Decision Lab` ทำให้เปิดเหมือนแอปได้ แต่ไม่จำเป็นต้อง
ติดตั้งจึงจะใช้งานได้

## ใช้งานแบบ local บน MacBook Air (ทางเลือก)

หัวข้อนี้ใช้เฉพาะเมื่อต้องการพัฒนา ทดสอบ หรือแก้โมเดล ไม่จำเป็นสำหรับการใช้งานทั่วไป

### 1. ตรวจ Python

เปิด Terminal แล้วรัน:

```bash
python3 --version
```

ต้องเป็น 3.11 ขึ้นไป หากไม่มี Python สามารถติดตั้ง Python 3.12 ผ่าน Homebrew หรือ
ดาวน์โหลดจาก python.org ได้

### 2. เปิดระบบ local

```bash
cd /Users/sarayutp/Project/10_FPL
./scripts/run_local.sh
```

ครั้งแรกจะใช้เวลาติดตั้ง dependencies หลังเห็นข้อความ `Open
http://127.0.0.1:8000` ให้เปิด URL ดังกล่าวใน Safari หรือ Chrome

อย่าดับเบิลคลิก `index.html` โดยตรง เพราะ Browser จะไม่อนุญาตให้หน้าเว็บอ่านไฟล์
JSON บางชนิด ต้องเปิดผ่าน local URL ข้างต้น

เมื่อต้องการหยุด ให้กลับมาที่ Terminal แล้วกด `Control+C`

### 3. อัปเดตข้อมูลในเครื่อง

```bash
cd /Users/sarayutp/Project/10_FPL
./scripts/update_data.sh
```

หาก local server เปิดอยู่ ให้ refresh หน้า Browser หลังคำสั่งจบ

## วิธีอ่านหน้า Dashboard

### เมนูและสถานะ (Phase 6)

เมนูหลักมี This Gameweek, Transfers, Planner, Players และ Diagnostics บนมือถือเลื่อนแถบเมนู
แนวนอนได้ ส่วน News & Risk, XI, Squad Lab, AI Briefing และประวัติ อยู่ในลิงก์ย่อยใต้ This Gameweek
ตาราง Players เลื่อนได้ในกรอบเพื่อดูนาที/ความมั่นใจครบโดยไม่ทำให้หน้าเว็บล้นจอ

`โหลดข้อมูลเว็บใหม่` อ่าน snapshot ที่เผยแพร่ไว้ ไม่ได้สั่ง FPL หรือ pipeline ให้เปลี่ยนทีมทันที
หาก Team ID ไม่ตรง ต้องปรับ pipeline ด้วย Team ID เดียวกันแล้วเผยแพร่ใหม่
ข้อมูลเก่า/ออฟไลน์/ผ่าน deadline จะปิดการบันทึกแผนใหม่ แต่ยังอ่านอ้างอิงได้
เมื่อ Briefing ขาดจะปิด copy/download; ถ้าทีมหรือเวลาของ Briefing ไม่ตรงกันจะหยุดคำแนะนำ
กรณีโหลดล้มเหลวให้ลองใหม่ ประวัติใน Browser จะไม่ถูกลบ

### ประวัติการตัดสินใจ

1. เลือกและบันทึกชิป/เส้นทางใน Planner ก่อน หากไม่เลือกจะบันทึก XI ทีมเดิมแบบไม่ย้ายตัว/ไม่ใช้ชิป
2. ใส่เหตุผลใน “ประวัติการตัดสินใจ” แล้วกดบันทึกก่อน deadline
3. หลังจบ GW กรอกคะแนนจริงสุทธิ ถ้าใช้ทีม/C/VC/ชิป/hit ตรงแผนจึงติ๊กยืนยันเพื่อแสดงส่วนต่าง
4. ส่งออก JSON สำรองเป็นระยะ เก็บสูงสุด 100 รายการ ไม่ลบอัตโนมัติ

ผลจริงเป็นข้อมูลที่คุณกรอกเอง ไม่ได้ตรวจจาก FPL. การลบต้องเปิดรายการแล้วกดยืนยันลบเฉพาะรายการ
ล้างข้อมูล Browser หรือเปลี่ยนอุปกรณ์ทำให้ประวัติไม่ตามไปด้วย; export เป็นสำรองไว้อ่าน ยังไม่มีระบบ import/ซิงก์
หากพื้นที่เต็มหรือประวัติเสียหาย ระบบจะไม่แสดงว่าบันทึกสำเร็จและไม่เขียนทับประวัติเดิม

Diagnostics แสดงรุ่นเว็บ/โมเดล/schema, snapshot timestamp, เวลาที่โหลดหน้า และสถานะแหล่งข้อมูล

### This Gameweek

ส่วนนี้เป็นหน้าเริ่มต้นและเป็นคำตอบหลักของระบบ ทุกช่องอ่านจาก
`gameweek_decision` ชุดเดียวกับไฟล์ JSON และ AI Briefing:

- `Transfer` ใช้ผลจาก Transfer Advisor ใน Browser เมื่อกรอกข้อมูลครบ มิฉะนั้นจะขอ
  Free Transfer และราคาขายจริงก่อนรับรองงบ
- `Starting XI` เลือก 11 คนจากทีมจริง 15 คนที่ FPL ประกาศล่าสุด
- `Captain / Vice` เลือกจากผู้เล่นใน XI ชุดเดียวกัน
- `Bench Order` เรียงผู้เล่นสนาม 1–3 และแสดงผู้รักษาประตูแยก
- `Chip` อ่านคำแนะนำจาก Planner หลาย Gameweek พร้อมกำไรคาดการณ์และค่าเสียโอกาส

สีหรือค่า `ความมั่นใจ` ไม่ใช่คำสั่งให้ทำตาม ให้เปิด `ดูเหตุผล` และตรวจข่าวใกล้ deadline
เสมอ หาก Team ID ไม่ตรง ข้อมูลเก่า หรือทีมจริงยังไม่พร้อม ระบบจะแสดง
`ยังแนะนำไม่ได้` แทนการคาดเดา

### News & Risk

ส่วนนี้รวม FPL availability, ข่าวที่ผู้ดูแลตรวจแล้ว และหลักฐานชั่วคราวที่คุณเพิ่มเอง:

- `ข้อเท็จจริง` ใช้กับ FPL/พรีเมียร์ลีกหรือคำแถลงสโมสรทางการ
- `ข้อสันนิษฐาน` ใช้กับ predicted lineup และข้อมูลที่คุณยืนยันเอง
- ทุกชิ้นต้องมี URL, เวลาเผยแพร่ และ Gameweek ที่หมดอายุ
- หลักฐานเกิน 24 ชั่วโมงหรือไม่ตรง Gameweek ยังแสดงในรายการเพื่อ audit แต่ไม่ปรับคำแนะนำ
- predicted lineup ปรับโมเดลได้ไม่เกิน ±15 นาทีและ ±15% โอกาสตัวจริง

กรอกนาทีหรือโอกาสตัวจริงเมื่อข่าวมีผลต่อบทบาท ระบบจะแสดงค่าก่อน–หลัง แล้วคำนวณ XI,
กัปตัน, bench และ Transfer Advisor ใหม่ทันที ข้อมูลนี้เก็บเฉพาะ Browser แยกตามฤดูกาลและ
Team ID กด `ล้างทั้งหมด` เพื่อคืนค่า snapshot ต้นทาง การเพิ่ม evidence ไม่ได้แก้ทีมใน FPL

ถ้าไม่มีข่าวสโมสรที่ตรวจแล้ว ระบบยังทำงานด้วย FPL status และความไม่แน่นอนของโมเดล
แต่จะแจ้งว่าใช้ fallback อย่าตีความว่า “ไม่มีข่าว” เท่ากับ “ลงแน่นอน”

### Transfer Advisor

ส่วน `Transfers` เปรียบเทียบสี่แผนจากทีมจริงชุดเดียวกัน:

- `Roll` ไม่เปลี่ยนผู้เล่นและแสดง Free Transfer รอบถัดไป
- `1 FT` และ `2 FT` แสดงผลเพิ่มสุทธิใน 1, 3 และ 5 Gameweeks
- `-4` ใช้ผู้เล่นเข้าเพิ่มจากจำนวน FT ที่มีและหัก 4 แต้มแล้วทุกช่วงเวลา

ให้กรอกจำนวน Free Transfer จากหน้า FPL และแก้เงินในธนาคารหากมีการเปลี่ยนแปลงที่ยังไม่
ปรากฏในข้อมูลสาธารณะ จากนั้นเปิดรายการ 15 คนและกรอก `ราคาขายจริง` เฉพาะคนที่แผนเสนอ
ให้ออก ระบบจะใช้ราคาปัจจุบันเพื่อค้นตัวเลือกเบื้องต้นเท่านั้น และจะแสดง
`ต้องยืนยันราคา` จนกว่าจะตรวจงบด้วยราคาขายจริงครบ

คำตัดสินมีสามระดับ: `ทำ`, `พิจารณา` และ `เก็บ FT` แผน -4 จะเป็น `ทำ` ได้ก็ต่อเมื่อ
ผลสุทธิหลัง hit และ downside ยังเป็นบวก พร้อมผ่านเกณฑ์นาที, โอกาสตัวจริงและ confidence
หากหลักฐานยังอ่อน ระบบอาจแสดงตัวเลขบวกแต่ให้เพียง `พิจารณา` ซึ่งเป็นพฤติกรรมที่ตั้งใจไว้

ค่า Free Transfer, bank และราคาขายเก็บเฉพาะใน Browser แยกตามฤดูกาลและ Team ID
กด `ล้างข้อมูล Transfer` เพื่อลบทั้งหมด การกดคัดลอก AI Briefing จะต่อ scenarios ที่
คำนวณใน Browser เข้าไปด้วย แต่ไฟล์ snapshot สาธารณะจะไม่บันทึกข้อมูลส่วนนี้

กติกาที่ใช้คือหนึ่ง Free Transfer ต่อ Gameweek, เก็บสะสมได้สูงสุดห้าครั้ง และ transfer
เกินโควตาครั้งละ -4 ตาม [FPL transfer rules](https://www.premierleague.com/en/news/2174907)
ส่วนราคาขายต้องใช้ purchase price ของบัญชีเพื่อคิดกำไรครึ่งหนึ่งตาม
[FPL FAQ](https://www.premierleague.com/en/news/4661030)

### Chip & Multi-GW Planner

หน้า `Planner` เปรียบเทียบ GW ถัดไป 3–6 สัปดาห์ตามช่วงที่โมเดลมองเห็น:

- แถวราย Gameweek แสดง formation, กัปตัน, xPts XI+C, TC gain และ BB gain
- การ์ด BB/TC/FH/WC แสดง `ใช้ตอนนี้`, `เก็บไว้` หรือ `ใช้ไม่ได้` พร้อม GW ที่ดีที่สุด,
  expected gain และ opportunity cost
- Bench Boost ใช้สำรองครบ 4 คนจากทีม 15 คนที่ผ่านกฎ
- Triple Captain ตรวจ expected minutes, โอกาสตัวจริง และคะแนนของกัปตัน
- Free Hit/Wildcard แยก scenario ทั้งทีม และต้องผ่าน confidence gate ก่อนขึ้น `ใช้ตอนนี้`
- transfer path หลัก/สำรองตรวจงบและโควตาทุกขั้นด้วยราคาปัจจุบัน

ประวัติชิปที่ public FPL ยืนยันจะถูกล็อก เช่น หากใช้ Bench Boost ใน GW2 แล้ว การ์ดจะเป็น
`ใช้ไม่ได้` ตลอดครึ่งฤดูกาลแรก คุณสามารถระบุ `กดรอใช้ก่อน deadline` หรือ `ใช้แล้ว` สำหรับ
สถานะที่ public history ยังไม่เห็น เลือกชิปหรือ `เก็บชิป` แล้วกด `บันทึกแผนที่เลือก`
ข้อมูลนี้อยู่ใน Browser ของฤดูกาลและ Team ID นั้นเท่านั้น เมื่อ Gameweek เปลี่ยน แผนเก่าจะ
แสดงว่าหมดอายุและต้องยืนยันใหม่

เลือก `แผนหลัก`, `แผนสำรอง` หรือ `Roll / ไม่ย้ายตัว` เพื่อบันทึกเส้นทางไปพร้อมชิปได้
BB/TC จะแสดงกำไรของชิปหลัง move แรกเมื่อบันทึกพร้อมเส้นทาง ส่วน FH/WC ต้องแยกจาก
regular transfer path และเลือก Roll ก่อนบันทึก เพราะใช้ทีมจำลองทั้งชุด
เมื่อ snapshot ใหม่, ข่าว, bank, FT หรือราคาขายเปลี่ยน แผนที่เก็บไว้จะขึ้นว่าต้องทบทวน
ไม่ถูกยืนยันตามข้อมูลเก่าโดยอัตโนมัติ

กำไรของ transfer path ใช้ XI+C เทียบ Roll และตรวจราคาขายที่กรอกใน Browser ทุกขั้น
หากยังไม่กรอก FT ระบบจำลอง 1 FT เริ่มต้นและระบุว่ายังไม่ยืนยัน ไม่ใช่คำแนะนำให้ติดลบ
Wildcard gain เทียบการไม่ย้ายตัว จึงต้องเทียบเส้นทาง FT ปกติประกอบด้วย

กติกา 2026/27 มีชิปสองชุดต่อฤดูกาล ใช้ได้หนึ่งชิปต่อ Gameweek ชุดแรกไม่ยกยอดหลัง GW19
และ Free Hit ใช้สอง Gameweek ติดต่อกันไม่ได้ ดู
[กติกาชิปทางการ](https://www.premierleague.com/en/news/4679879/whats-happening-with-fpl-chips-in-202627)
และ [FAQ](https://www.premierleague.com/en/news/4661030) ระบบเป็น read-only และไม่กดใช้ชิป
หรือย้ายตัวใน FPL

### วิธีอ่าน xP v2

- `xPts` / expected points คือคะแนน FPL ที่คาดก่อนคูณกัปตัน
- `Ranking score` ใช้เรียงผู้เล่นโดยลดน้ำหนักตัวเลือกที่ confidence ต่ำ ไม่ใช่คะแนน FPL
- `Expected minutes` และ `% ตัวจริง` ใช้บอกความเสี่ยงด้านบทบาท
- ช่วงคะแนน เช่น `2.4–12.3` สื่อความไม่แน่นอน ไม่ใช่การรับประกันว่าผลจะอยู่ในช่วง
- `small_sample` หรือ `early_season` หมายถึงโมเดลยังพึ่ง prior จากตำแหน่ง/ราคาเป็นหลัก

ช่วงต้นฤดูกาล confidence ต่ำเป็นพฤติกรรมที่ตั้งใจไว้ อย่าเพิ่มความมั่นใจด้วยการดูทศนิยม
หลายตำแหน่ง ให้ให้น้ำหนักข่าวตัวจริงและ expected minutes มากกว่าส่วนต่างเล็ก ๆ ของ xPts

### ภาพรวม

- `Team Source of Truth` แสดงชื่อทีม, ผู้จัดการ, Team ID, ฤดูกาล, Gameweek และแหล่งทีม
- `ทีมที่ประกาศล่าสุด` คือ picks หลัง deadline ที่ FPL เปิดเป็นสาธารณะ ไม่รวมการแก้ทีม
  ที่ยังไม่ผ่าน deadline
- `Next decision` แสดงเวลานับถอยหลังตาม timezone ของเครื่อง
- `xPts XI ทีมจริง + กัปตัน` คือคะแนนคาดการณ์ของ XI จากทีมที่มีอยู่จริง รวมแต้มกัปตันสองเท่า
- `Captain Radar` แสดงเฉพาะตัวเลือกที่ผ่านเกณฑ์นาที/โอกาสตัวจริงในทีมจริง
- แถบความสดของข้อมูลจะเตือนเมื่อ snapshot เก่ากว่า 24 ชั่วโมง

### Wildcard Lab

Optimizer เลือก 15 คนภายใต้กติกา:

- GKP 2, DEF 5, MID 5, FWD 3

- กัปตันและรองกัปตันอยู่คนละสโมสรเพื่อลดความเสี่ยงร่วม

ทีมนี้เป็น baseline สำหรับทดลองสร้างทีมใหม่ 15 คนหรือ Wildcard ไม่ใช่แผน transfer
ประจำสัปดาห์ และไม่จำเป็นต้องลอกทุกคน

### Squad Lab

ก่อน GW1 ให้กด `ใช้ทีมแนะนำ` แล้วปรับทีละคน หรือเลือกผู้เล่นจาก Player Explorer

- ทีมถูกเก็บไว้ใน Browser ด้วย `localStorage`
- ทีมถูกแยกตามฤดูกาลและ Team ID จึงไม่ปะปนเมื่อใช้ Browser เดียวกันหลายทีม
- เพดานงบของ Lab ใช้ค่าสูงสุดระหว่าง 100.0m กับมูลค่าทีมล่าสุดจาก FPL เพื่อรองรับทีมจริงที่ราคาขยับแล้ว
- หากล้างข้อมูลเว็บไซต์หรือเปลี่ยน Browser ทีมทดลองจะไม่ตามไปด้วย
- กด `ส่งออก JSON` เพื่อสำรองรายชื่อ Player IDs
- ระบบบล็อกการเพิ่มผู้เล่นเมื่อเกินงบ, ตำแหน่ง หรือ 3 คนต่อสโมสร
- `โอกาสอัปเกรด` เป็น swap ตำแหน่งเดียวที่อยู่ในงบและเพิ่ม expected points

งบใน Lab ยังเป็นค่าประมาณจากข้อมูลสาธารณะ เพราะ FPL ไม่เปิดราคาขายรายคนของบัญชี
จึงต้องยืนยันงบจริงในหน้า Transfers ก่อนทำรายการเสมอ

หลัง deadline เมื่อ FPL เปิด picks สาธารณะ ปุ่ม `ใช้ทีม FPL ล่าสุด` จะปรากฏ

## Routine ที่แนะนำต่อ Gameweek

### 3–5 วันก่อน deadline

1. เปิด Dashboard ออนไลน์และตรวจป้ายความสดของข้อมูล
2. ดูโปรแกรม 5 GW ไม่ไล่ตามคะแนนสัปดาห์เดียว
3. เปรียบเทียบ Roll/1 FT/2 FT ใน Transfer Advisor และดูช่วง 3–5 GW
4. หลีกเลี่ยง early transfer หากผู้เล่นมีเกมกลางสัปดาห์

### 24 ชั่วโมงก่อน deadline

1. เปิด AI Briefing และคัดลอกไป ChatGPT
2. ให้ ChatGPT ค้นข่าว press conference และ predicted lineup ล่าสุด
3. นำข่าวที่มี URL/เวลาใส่ `News & Risk` แล้วดูว่า XI/กัปตันเปลี่ยนหรือไม่
4. ตรวจราคาและราคาขายจริงในหน้า Transfers ของ FPL
5. เทียบความคุ้มของ hit: คะแนนเพิ่มคาดการณ์ต้องมากกว่าต้นทุนและความไม่แน่นอน

### 15–30 นาทีก่อน deadline

1. ตรวจ starting XI, captain, vice และ bench order
2. ตรวจธงบาดเจ็บ/เลื่อนเกมจาก FPL อีกครั้ง
3. กด Save My Team ใน FPL ด้วยตัวเอง
4. อย่ารอวินาทีสุดท้าย เพราะเว็บอาจหน่วง

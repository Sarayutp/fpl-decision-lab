# คู่มือใช้งาน FPL Decision Lab

ระบบนี้ช่วยวิเคราะห์ทีม Fantasy Premier League ของคุณ โดยรวมทีมที่ FPL เปิดเผย โปรแกรมแข่ง คะแนนคาดการณ์ ข่าวความเสี่ยง และแผนย้ายตัวไว้ในที่เดียว เป้าหมายคือช่วยให้ตัดสินใจอย่างมีเหตุผล ไม่ใช่รับประกันคะแนนหรือเล่นแทนคุณ

> **เรื่องสำคัญที่สุด:** เว็บนี้ไม่เข้าสู่บัญชี FPL ไม่ย้ายตัว ไม่จัดทีมจริง และไม่กดใช้ชิปให้คุณ ทุกแผนเป็นการจำลอง คุณต้องกลับไปยืนยันใน FPL เอง รวมถึง Bench Boost ด้วย

เอกสารนี้อธิบายพฤติกรรมของเว็บ ไม่ใช่ข่าวนักเตะล่าสุด ตัวเลขในตัวอย่างเป็นข้อมูลสมมติ ควรตรวจเวลาข้อมูล ทีมที่ใช้วิเคราะห์ และ deadline ทุกครั้ง

## 01. เริ่มใช้งานใน 5 ขั้นตอน

สิ่งที่ควรเตรียม: หน้า FPL ของคุณ, Team ID, จำนวน Free Transfer ที่เหลือ, เงินในธนาคาร และราคาขายจริงของคนที่กำลังจะขาย ไม่ต้องใช้ OpenAI API key และไม่ต้องกรอกรหัสผ่าน FPL ในเว็บนี้

1. **เปิดระบบและตรวจทีม** — เข้า [FPL Decision Lab](https://sarayutp.github.io/fpl-decision-lab/) อ่านกล่อง `Team Source of Truth` ให้ชื่อทีมและ Team ID ตรงกับทีมของคุณ ถ้าไม่ตรง ให้หยุดก่อน
2. **ตรวจความสด** — ดูเวลาที่สร้างข้อมูลและ GW เป้าหมาย ข้อมูลเกิน 24 ชั่วโมง ออฟไลน์ หรือผ่าน deadline ไม่ควรใช้ยืนยันแผนใหม่
3. **อ่านคำตอบหลัก** — ใน `This Gameweek` ดู Transfer, Starting XI, Captain / Vice, Bench และ Chip แล้วเปิด `ดูเหตุผล` เพื่ออ่านข้อจำกัด
4. **เติมสิ่งที่ข้อมูลสาธารณะไม่มี** — ใน `Transfers` กรอก FT เงินในธนาคาร และราคาขายจริงที่เกี่ยวข้อง จากนั้นตรวจข่าวใน `News & Risk` และเทียบทางเลือกใน `Planner` หรือ `เทียบแผน A/B`
5. **ยืนยันด้วยตัวเอง** — ตรวจราคา ข่าว XI กัปตัน รองกัปตัน สำรอง และชิปอีกครั้งใน FPL แล้วบันทึกทีมจริงก่อน deadline หากต้องการทบทวนภายหลัง ให้บันทึกการตัดสินใจในเว็บนี้ด้วย

เมื่อทำครบ คุณควรรู้ว่า “แผนคืออะไร ใช้ข้อมูลชุดไหน มีความเสี่ยงอะไร และต้องตรวจอะไรอีก” ไม่ใช่เพียงเห็นว่าคนใดมีคะแนนคาดการณ์สูงสุด

## 02. เปิดเว็บที่ไหน และต้องติดตั้งไหม

### ใช้งานปกติ: เปิดเว็บออนไลน์

เปิด [หน้า Dashboard](https://sarayutp.github.io/fpl-decision-lab/) บนคอมพิวเตอร์หรือมือถือ ไม่ต้องเปิด MacBook ทิ้งไว้ ไม่ต้องเปิด Terminal และไม่ต้องติดตั้ง Python การติดตั้งเป็นแอป PWA เป็นทางเลือก หาก Browser มีคำสั่งติดตั้งหรือเพิ่มหน้าจอหลักก็ใช้ได้ แต่ไม่จำเป็น

### ใช้งานในเครื่อง: สำหรับพัฒนาหรือทดสอบ

ที่อยู่ `http://127.0.0.1:8000` คือเว็บจากเครื่องของคุณ ต้องเปิด local server อยู่จึงจะเข้าได้ จากมือถือ `127.0.0.1` หมายถึงมือถือเครื่องนั้น ไม่ใช่ MacBook ให้ใช้เว็บออนไลน์สำหรับการใช้งานทั่วไป

ข้อมูลที่บันทึกใน Browser ของเว็บออนไลน์และ local **ไม่ใช้ร่วมกัน** แม้หน้าตาเหมือนกัน การเปลี่ยนพอร์ต เช่น 8000 เป็น 8011 ก็ถือเป็นคนละพื้นที่เก็บข้อมูล

### เมื่อไม่มีอินเทอร์เน็ต

หลังเคยเปิด Dashboard และระบบแคชสำเร็จ อาจอ่านหน้าเว็บและคู่มือล่าสุดที่เก็บไว้ได้ แต่ข้อมูลนั้นไม่ได้สดขึ้นตามเวลา เว็บจะปิดการบันทึกแผนใหม่และการสร้างการ์ดเมื่ออยู่ในสถานะออฟไลน์ ไม่ควรใช้ข้อมูลแคชตัดสินใจใกล้ deadline

คู่มือเป็นหน้าแยก ไม่ต้องรอข้อมูลทีมโหลดสำเร็จ หากเพิ่งเข้าเป็นครั้งแรกขณะไม่มีอินเทอร์เน็ต ยังต้องใช้คู่มือที่ดาวน์โหลดเก็บไว้ล่วงหน้า

## 03. แผนที่เมนู: อยากทำอะไร ให้เปิดตรงไหน

เมนูหลักอยู่ด้านบน บนจอแคบเลื่อนแถบเมนูแนวนอนได้

| เมนู | ใช้เมื่อ | สิ่งที่จะได้ |
| --- | --- | --- |
| This Gameweek | ต้องการคำตอบสำหรับ GW นี้ | แผนย้ายตัว XI กัปตัน สำรอง และชิป |
| Transfers | ต้องการเทียบไม่ย้าย / ย้าย / ติดลบ | ผลสุทธิในหลาย GW พร้อมการตรวจงบ |
| Planner | วางแผนชิปและเส้นทางย้ายตัว | เปรียบเทียบใช้ตอนนี้กับเก็บไว้ |
| Players | ค้นหาและเปรียบเทียบผู้เล่น | ราคา โปรแกรม นาที คะแนนคาดการณ์และความเสี่ยง |
| Diagnostics | ข้อมูลไม่มา หรือสงสัยว่าเว็บเก่า | รุ่นเว็บ เวลาข้อมูล และสถานะแหล่งข้อมูล |
| วิธีใช้งาน | เริ่มเรียนรู้หรือหาวิธีแก้ปัญหา | คู่มือฉบับนี้ สารบัญ ดาวน์โหลด และพิมพ์ |

ลิงก์ย่อยใต้ `This Gameweek` ได้แก่ `News & Risk`, `XI ของฉัน`, `Squad Lab`, `AI Briefing`, `ประวัติการตัดสินใจ` และ `เทียบแผน A/B` ส่วนการ์ดสำหรับแชร์อยู่ภายในส่วน A/B

## 04. ตรวจว่าเป็นทีมปัจจุบันของเราจริงหรือไม่

เปิด [Team Source of Truth](https://sarayutp.github.io/fpl-decision-lab/#identity) แล้วตรวจชื่อทีม Team ID ฤดูกาล GW ของทีมที่เปิดเผย และ GW เป้าหมายที่กำลังวิเคราะห์

**Team ID** คือเลขประจำทีม ดูจาก URL หน้า Points หรือประวัติทีมใน FPL ที่มีรูปแบบ `/entry/เลขทีม/...` อย่าใช้ League ID แทน และตรวจใหม่เมื่อเปลี่ยนฤดูกาล

### ทำไมทีมอาจไม่เหมือนหน้า My Team

เว็บนี้ใช้ picks ที่ FPL เปิดเป็นสาธารณะหลัง deadline จึงอาจยังไม่เห็นการย้ายตัวหรือจัดทีมที่คุณเพิ่งทำสำหรับ GW ถัดไป ข้อความ “ทีมที่ประกาศล่าสุด” ไม่ได้แปลว่าอ่าน My Team แบบสดจากบัญชีส่วนตัว

ตัวอย่าง: คุณขายผู้เล่นไปแล้ว แต่ FPL ยังไม่เปิด picks ของ GW ใหม่ เว็บอาจยังวิเคราะห์จากผู้เล่นเดิม **อย่าขายซ้ำหรือทำตาม XI เดิมโดยไม่ตรวจ** และอย่าใช้ทีมทดลองใน Squad Lab เป็นหลักฐานว่า snapshot ทีมจริงถูกแก้แล้ว

### ช่อง Team ID ทำอะไร

1. กรอกเลขใน `Team ID ที่คุณตั้งใจดู`
2. กด `ตรวจสอบ Team ID`
3. ถ้าตรงกับข้อมูลที่เผยแพร่ ระบบจึงอนุญาตให้ใช้คำแนะนำของทีมนั้น
4. ถ้าไม่ตรง ระบบหยุดคำแนะนำและเครื่องมือสำคัญ ให้ผู้ดูแลสร้างและเผยแพร่ snapshot ของทีมที่ถูกต้องก่อน

ช่องนี้เป็น **ตัวตรวจความตรงกัน ไม่ใช่ปุ่มดึงทีมอื่นทันที** การกรอกเลขไม่ได้ทำให้เว็บเปลี่ยนผู้เล่นตามบัญชีนั้น อย่าเปลี่ยนเลขให้ตรง snapshot เพียงเพื่อให้ปุ่มใช้งานได้ หากไม่ใช่ทีมที่คุณต้องการ

## 05. อ่านคำตอบ This Gameweek และจัด XI

เปิด [This Gameweek](https://sarayutp.github.io/fpl-decision-lab/#this-gameweek) แล้วอ่านทั้งห้าส่วนร่วมกัน

| คำตอบ | ความหมาย | สิ่งที่ต้องตรวจเอง |
| --- | --- | --- |
| Transfer | ทางเลือกจากทีมตั้งต้น พร้อมเงื่อนไข FT/ราคา | คนที่ขายยังอยู่ในทีมจริงหรือไม่ งบจริงพอหรือไม่ |
| Starting XI | 11 คนที่แนะนำจากทีม 15 คนใน snapshot | ตรงกับทีมหลังย้ายตัวของคุณหรือไม่ |
| Captain / Vice | กัปตันและรองกัปตันจาก XI | ข่าวตัวจริง ความฟิต และโปรแกรมล่าสุด |
| Bench Order | ลำดับผู้เล่นสนามสำรอง 1–3 และ GKP แยก | ลำดับใน FPL ตรงกันและ formation ถูกกติกา |
| Chip | ใช้หรือเก็บชิป พร้อมบริบทหลาย GW | ชิปยังใช้ได้จริง และยืนยันใน FPL หรือยัง |

เปิด `XI ของฉัน` เพื่อดูสนามและรายชื่อชัดขึ้น `C` คือกัปตัน `VC` คือรองกัปตัน ผู้รักษาประตูสำรองแยกจากลำดับผู้เล่นสนาม ไม่ใช่คนที่นำมาแทนผู้เล่นสนามได้

กรณีเลือก transfer path ใน Planner ให้ตรวจ XI ของแผนนั้นด้วย อย่าเอา XI ทีมเดิมก่อนย้ายตัวไปใช้กับทีมหลังย้ายตัวโดยอัตโนมัติ

หากเห็น `ยังแนะนำไม่ได้` ให้ดูเหตุผลเรื่องทีม ข้อมูล หรือ deadline ก่อน การไม่มีคำแนะนำเป็นการป้องกันการใช้ฐานข้อมูลผิด ไม่ได้แปลว่าควรเลือกผู้เล่นอันดับแรกแทนเอง

## 06. คำศัพท์และตัวเลขที่ต้องเข้าใจ

| คำ | ความหมายแบบง่าย |
| --- | --- |
| GW / Gameweek | รอบคะแนนของเกม ไม่จำเป็นต้องตรงกับสัปดาห์ปฏิทินเสมอ |
| Deadline | เวลาสุดท้ายสำหรับยืนยันแผนของ GW นั้น ตรวจเวลาและ timezone ที่แสดง |
| Snapshot | ชุดข้อมูลที่ถ่ายไว้ ณ เวลาหนึ่ง ไม่ใช่ข้อมูลบัญชีแบบสดตลอดเวลา |
| FT / Free Transfer | สิทธิ์ย้ายตัวฟรีที่เหลือ ต้องตรวจจาก FPL |
| Roll | ไม่ย้ายตัว เพื่อเก็บสิทธิ์ไว้ใช้ภายใต้กติกาปัจจุบัน |
| Hit / -4 | ต้นทุนคะแนนจากการย้ายเกินสิทธิ์ฟรี |
| xPts / Expected points | คะแนน FPL ที่โมเดลคาดของผู้เล่น ก่อนคูณกัปตัน |
| Ranking score | คะแนนช่วยเรียงตัวเลือกที่คำนึงถึงความมั่นใจ ไม่ใช่คะแนน FPL |
| Expected minutes / % ตัวจริง | นาทีและโอกาสออกสตาร์ตที่คาด ไม่ใช่รายชื่อยืนยัน |
| Confidence | ระดับความเชื่อมั่นจากข้อมูลที่มี ไม่ใช่โอกาสชนะหรือการรับประกัน |
| Downside / ช่วงคะแนน | มุมมองความเสี่ยงและความไม่แน่นอน ผลจริงอาจอยู่นอกช่วง |
| Opportunity cost | สิ่งที่อาจเสียไปเมื่อใช้ตอนนี้ เช่น ไม่มีชิปไว้ใช้ใน GW ที่ดีกว่า |
| Blank / Double GW | ไม่มีนัด / มีมากกว่าหนึ่งนัดใน GW เป้าหมาย ต้องตรวจโปรแกรมล่าสุด |
| small_sample / early_season | ตัวอย่างยังน้อย โมเดลยังพึ่งข้อมูลตั้งต้นมาก |

ตัวอย่างสมมติ: A มี xPts 5.2 และ B มี 5.0 ส่วนต่างเพียง 0.2 ไม่ทำให้ A เป็นคำตอบแน่นอน หาก A มีความเสี่ยงลงสำรอง ข่าวใหม่อาจสำคัญกว่าส่วนต่างนี้

> โมเดลยังต้องสะสมผล backtest เพิ่มเติม อย่าตีความทศนิยมหลายตำแหน่งว่าแม่นยำ และอย่าสรุปว่าระบบพิสูจน์แล้วว่าชนะวิธีพื้นฐานหรือช่วยเพิ่มคะแนนจริง

## 07. Transfers: เทียบแผนและตรวจงบจริง

เปิด [Transfers](https://sarayutp.github.io/fpl-decision-lab/#transfer-advisor)

1. เปิดหน้า Transfers ใน FPL ควบคู่กัน ดู FT ที่เหลือกับเงินในธนาคาร ณ ตอนนี้
2. เลือก `Free Transfer ปัจจุบัน` และกรอก `เงินในธนาคารปัจจุบัน` หน่วย m เช่น 0.5 หมายถึง £0.5m
3. เปิด `กรอกราคาขายจริงของผู้เล่น 15 คน` แล้วกรอกราคาที่ FPL ให้ขายได้ โดยเฉพาะคนที่แผนเสนอให้ออก
4. อ่านแผน Roll, 1 FT, 2 FT และ -4 โดยดูคนเข้า–ออก เงินคงเหลือ และผลเพิ่มสุทธิช่วง 1, 3 และ 5 GW
5. ตรวจสถานะ `ต้องยืนยันราคา` และเหตุผลคำตัดสิน `ทำ`, `พิจารณา` หรือ `เก็บ FT` ก่อนเลือกแผน

**ราคาขายไม่จำเป็นต้องเท่าราคาตลาด** ใช้ราคาที่ FPL ให้บัญชีคุณขายได้ ไม่ใช่ราคาซื้อใน Players ถ้าราคายังไม่ครบ งบจากราคาปัจจุบันเป็นเพียงค่าประมาณ

แผน `-4` หัก hit แล้วในผลสุทธิ ไม่ต้องหักซ้ำ กำไรช่วง 1/3/5 GW เป็นทางเลือกของช่วงประเมิน ไม่ใช่สามจำนวนที่นำมาบวกกัน

ตัวอย่างสมมติ: แผนย้ายคาดว่าเพิ่ม 5 แต้มใน 3 GW แต่เสีย hit 4 แต้ม เหลือสุทธิ 1 แต้มก่อนพิจารณาความไม่แน่นอน ไม่ใช่เหตุผลเพียงพอที่จะบอกว่าต้องติดลบ

### ขอบเขตของแบบฟอร์มรุ่นนี้

เลือก FT ได้ 1–5 และเงินในธนาคารได้ 0–30m ถ้าบัญชีจริงมี FT เหลือ 0 หรือเงินนอกช่วงนี้ **อย่ากรอกค่าปลอมให้ระบบผ่าน** ใช้ผลเป็นเพียงข้อมูลอ้างอิงและตรวจแผนใน FPL เอง โดยเฉพาะเมื่อย้ายตัวไปแล้วแต่ public picks ยังเป็นชุดเก่า

ปุ่ม `ล้างข้อมูล Transfer` ล้างค่าที่กรอกในส่วนนี้ ไม่ได้ลบผู้เล่นหรือคืน transfer ใน FPL

## 08. News & Risk: ใส่ข่าวใหม่อย่างมีหลักฐาน

เปิด [News & Risk](https://sarayutp.github.io/fpl-decision-lab/#risk-desk) อ่านสถานะแหล่งข้อมูลและ Risk Check ก่อน ข่าวที่ไม่มีในรายการไม่ได้แปลว่านักเตะฟิตหรือได้ลงแน่นอน

### เพิ่มหลักฐานทีละช่อง

1. เลือก `ผู้เล่นในทีมจริง` ที่ข่าวเกี่ยวข้อง
2. เลือก `ประเภทแหล่ง` ให้ตรง เช่น ข่าวทางการ หรือ predicted lineup อย่าเลือกทางการเพียงเพื่อให้น้ำหนักมากขึ้น
3. เลือก `หมวดความเสี่ยง` และเขียน `สรุปข่าวหรือเหตุผล` ให้ชัดว่าเกิดอะไร
4. ใส่ `ลิงก์แหล่งข่าว` ที่เปิดอ่านได้ ใช้หน้าข่าวต้นทางเมื่อมี
5. กรอก `เวลาเผยแพร่` ตามข่าว ไม่ใช่เวลาที่เพิ่งอ่าน และตรวจให้ตรงกับเวลาเครื่อง
6. กรอก `หมดอายุหลัง GW` เพื่อไม่ให้ข่าวชั่วคราวมีผลต่อเนื่องโดยไม่ตั้งใจ
7. หากมีเหตุผลพอจึงกรอก `คาดนาทีใหม่` 0–90 และ `โอกาสตัวจริง %` 0–100 สองช่องนี้ไม่บังคับ
8. กด `บันทึกและคำนวณใหม่` อ่านผลก่อน–หลัง รวมถึง XI กัปตัน สำรอง และแผนย้ายตัวที่เปลี่ยน

ระบบแยกแหล่งทางการจากข้อสันนิษฐาน แต่ **การเลือกประเภทแหล่งไม่ได้ทำให้ระบบตรวจว่าข่าวจริงโดยอัตโนมัติ** ผู้กรอกต้องตรวจความน่าเชื่อถือเอง

หลักฐานเกิน 24 ชั่วโมง หมดอายุ หรือไม่ตรง GW ยังอาจแสดงเพื่อทบทวน แต่ไม่ปรับคำแนะนำใหม่ Predicted lineup มีเพดานปรับไม่เกิน ±15 นาทีและ ±15 จุดเปอร์เซ็นต์ของโอกาสตัวจริง ไม่ใช่รายชื่อยืนยัน

ข่าวเพิ่มเองเก็บเฉพาะ Browser กด `ล้างทั้งหมด` ใน News & Risk เพื่อล้างหลักฐานเพิ่มเองและกลับไปใช้ snapshot ไม่ได้ลบข่าวต้นทางจากระบบส่วนกลาง

## 09. Planner: เลือกชิปและวางเส้นทางหลาย GW

เปิด [Planner](https://sarayutp.github.io/fpl-decision-lab/#chip-planner) อ่านช่วง GW ที่ใช้ประเมินก่อน รุ่นนี้วางบริบทล่วงหน้า 3–6 GW ตามข้อมูลที่พร้อม และแยกการย้ายตัวปกติจากทีมสำหรับ Wildcard / Free Hit

| ชิป | แนวคิดหลัก | คำถามก่อนใช้ |
| --- | --- | --- |
| Bench Boost | นับคะแนนสำรองด้วยใน GW ที่ใช้ | สำรองทั้งสี่มีโอกาสลงและโปรแกรมดีจริงไหม |
| Triple Captain | กัปตันได้ตัวคูณสามแทนสอง | นาทีและโปรแกรมของกัปตันน่าเชื่อถือแค่ไหน |
| Free Hit | เปลี่ยนทีมชั่วคราวหนึ่ง GW ก่อนกลับทีมเดิม | ทีมชั่วคราวดีกว่าเดิมพอหรือควรเก็บไว้ |
| Wildcard | ย้ายผู้เล่นโดยไม่เสีย hit ในช่วงที่ใช้ชิป | ทีมใหม่ดีหลาย GW หรือดีแค่สัปดาห์เดียว |

คำอธิบายพื้นฐานอ้างอิง [คู่มือเริ่มเล่นจาก Premier League](https://www.premierleague.com/ar/news/1252542) ส่วนจำนวนชิป วันหมดอายุ เงื่อนไข FT และข้อห้ามใช้ติดกัน ให้ตรวจ [กติกา FPL ปัจจุบัน](https://fantasy.premierleague.com/help/rules) และสถานะบัญชีจริงก่อนยืนยันเสมอ

### ทดลองและบันทึก

1. อ่านว่าจะใช้ตอนนี้หรือเก็บไว้ พร้อมกำไรคาดการณ์ ค่าเสียโอกาส และคำเตือน
2. ดูแผนราย GW และตารางชิป อย่าเลือกจากคะแนน GW เดียว
3. เลือกชิปหรือเก็บชิป แล้วเลือก transfer path ที่มีให้ หากไม่ย้ายกด `เลือก Roll / ไม่ย้ายตัว`
4. ตรวจ XI+C, hit และงบหลังแต่ละ move ประวัติชิปที่ FPL ยืนยันจะล็อกไว้ ส่วนสถานะที่คุณปรับเป็นข้อมูลใน Browser
5. ถ้าต้องการเทียบสองทางเลือก ไปเก็บ A/B ก่อน ถ้าตัดสินใจแล้วกด `บันทึกแผนที่เลือก`
6. ทำรายการและกดใช้ชิปใน FPL เอง การบันทึก Planner ไม่ใช่การใช้ชิปจริง

หากยังไม่กรอก FT ระบบอาจจำลองเริ่มต้น 1 FT พร้อมระบุว่ายังไม่ยืนยัน อย่าใช้แทนบัญชีจริง กำไร Wildcard เทียบกับไม่ย้ายตัว จึงควรเทียบเส้นทาง FT ปกติด้วย

แผนที่บันทึกจะตรวจว่าตรงกับ snapshot ข่าว ราคา และบริบทปัจจุบันหรือไม่ หากไม่ตรง ต้องทบทวนและบันทึกใหม่ `ล้างแผนใน Browser` ล้างแผนในเว็บ ไม่ได้ยกเลิกชิปใน FPL

## 10. เปรียบเทียบ A/B โดยไม่เปลี่ยนแผนที่บันทึก

เปิด [เทียบแผน A/B](https://sarayutp.github.io/fpl-decision-lab/#scenario-comparison) เพื่อเก็บฉบับร่างจาก Planner สองทางเลือก

1. เลือกชิปและเส้นทางแรกใน Planner ยังไม่จำเป็นต้องกดบันทึก Planner
2. ใส่ `ชื่อแผนที่จะเก็บ` เช่น “เก็บชิปรอข่าว” แล้วกด `เก็บฉบับร่างเป็น A`
3. เปลี่ยนฉบับร่างใน Planner เป็นทางเลือกที่สอง ตั้งชื่อแล้วกด `เก็บฉบับร่างเป็น B`
4. อ่านตาราง: XI, C/VC, สำรอง, ชิป, hit, งบ, คะแนนคาดการณ์ และความเสี่ยง
5. ถ้าจะใช้ทางใด ให้กลับไปเลือกและบันทึกใน Planner เอง A/B ไม่ใช้แผนให้คุณ

`B − A` เทียบคะแนนสุทธิของ **GW เป้าหมายเดียวกันเท่านั้น** รวมผลตัวคูณชิปและหัก hit แต่ไม่รวมมูลค่าชิปหรือ FT ในอนาคต จึงไม่ใช่คำสั่งให้ใช้ชิปหรือติดลบเมื่อเห็นค่าบวก

เมื่อ snapshot โมเดล ข่าว หรือราคาเปลี่ยน จะหยุดแสดงส่วนต่างจนเก็บ A/B ใหม่ให้ตรงบริบททั้งคู่ แผนเก่าอ่านทบทวนได้ แต่ไม่ควรเทียบกับแผนจากข้อมูลคนละชุด

เก็บได้สองช่องต่อทีม/ฤดูกาล/GW การแทนที่ทับเฉพาะช่องนั้น ควร `ส่งออกแผน A/B JSON` ก่อนหากต้องการเก็บฉบับเดิม ลบ A ไม่ลบ B, Planner หรือ Journal ไฟล์ JSON เป็นสำรองไว้อ่าน **ยังนำกลับเข้าเว็บไม่ได้**

## 11. สร้างการ์ดสำหรับแชร์แผน

ใน A/B เปิด `สร้างการ์ดจากแผน A/B สำหรับแชร์`

1. ต้องมี A หรือ B ที่ตรงข้อมูลปัจจุบันก่อน
2. เลือกช่องใน `แผนสำหรับสร้างการ์ด` แล้วกด `ดูตัวอย่างการ์ด`
3. อ่านภาพและข้อความ ตรวจผู้เล่น ชิป hit และคำเตือนก่อนส่งต่อ
4. เลือก `ดาวน์โหลดการ์ด PNG`, `ดาวน์โหลดข้อความการ์ด` หรือ `คัดลอกข้อความการ์ด`
5. คุณเลือกปลายทางและส่งเอง เว็บไม่โพสต์หรืออัปโหลดอัตโนมัติ

การ์ดไม่ใส่ชื่อทีม ผู้จัดการ Team ID งบ ราคาขาย ชื่อแผนที่ตั้งเอง และบันทึกส่วนตัว แต่ยังเผยรายชื่อผู้เล่นและแผนของคุณ **ไม่รับรองว่าผู้รับจะระบุเจ้าของทีมไม่ได้**

อย่าใช้ A/B JSON แทนการ์ด เพราะมีรายละเอียดส่วนตัวมากกว่า เมื่อข้อมูลเปลี่ยนหรือเปลี่ยน/แทนที่/ลบช่อง ตัวอย่างเดิมจะถูกล้าง ต้องสร้างใหม่ ขณะข้อมูลเก่า ออฟไลน์ ผ่าน deadline หรือทีมไม่ตรง จะสร้างและส่งออกการ์ดใหม่ไม่ได้

ไฟล์ที่ดาวน์โหลดหรือข้อความที่คัดลอกแล้วไม่อัปเดตและเรียกคืนจากเว็บนี้ไม่ได้ ถ้า PNG สร้างไม่ได้หรือฟอนต์ต่างบนอีกอุปกรณ์ ให้ใช้ข้อความแทน ถ้าคัดลอกถูกปฏิเสธ ให้ดาวน์โหลดข้อความแทน

## 12. ประวัติการตัดสินใจ: บันทึกก่อนแข่ง ทบทวนหลังจบ

เปิด [ประวัติการตัดสินใจ](https://sarayutp.github.io/fpl-decision-lab/#decision-log)

1. เลือกและบันทึกแผนใน Planner ก่อน หากไม่มีแผนที่เลือก ระบบบันทึก XI ทีมเดิมแบบไม่ย้ายตัวและไม่ใช้ชิป
2. ใส่ `เหตุผลที่เลือกแผนนี้` เช่น “เก็บ FT เพราะข่าวตัวจริงยังไม่ชัด” หลีกเลี่ยงข้อมูลลับ
3. กด `บันทึกการตัดสินใจ` ก่อน deadline แล้วตรวจว่ารายการใหม่ปรากฏจริง
4. หลังจบ GW เปิดรายการและกรอกคะแนนจริง **สุทธิหลัง hit**
5. ยืนยันว่าเล่นตรงแผนเฉพาะเมื่อทีม C/VC ชิปและ hit ตรงที่บันทึกจริง จึงใช้ส่วนต่างคาดการณ์กับผลจริงทบทวนได้
6. กด `ส่งออกประวัติ JSON` สำรองเป็นระยะ เก็บไฟล์ในที่ส่วนตัว

คะแนนจริงเป็นค่าที่กรอกเอง ระบบไม่ได้ตรวจจากบัญชี FPL หากเปลี่ยนใจตอนท้าย อย่ายืนยันว่าตรงแผนเดิม ส่วนต่างคะแนน GW เดียวไม่ใช่หลักฐานว่าโมเดลดีหรือแย่แน่นอน

เก็บสูงสุด 100 รายการ ไม่ลบเก่าอัตโนมัติ การลบต้องเปิดและยืนยันรายการนั้น ถ้าพื้นที่เต็มหรือข้อมูลเสียหาย ระบบจะไม่อ้างว่าบันทึกสำเร็จและไม่ควรเขียนทับประวัติเดิม ยังไม่มี import หรือ sync

## 13. Players: ค้นตัวเลือกให้ตรงโจทย์

เปิด [Players](https://sarayutp.github.io/fpl-decision-lab/#players)

1. พิมพ์ชื่อในช่องค้นหา หรือล้างข้อความเพื่อดูทุกคน
2. กรองตำแหน่งและสโมสรเพื่อเทียบคนที่ทดแทนกันได้
3. เรียงตามคะแนนคาดการณ์ GW ถัดไป / 5 GW, ranking score, ความคุ้มค่า, ownership หรือราคา
4. อ่านโปรแกรม นาที โอกาสตัวจริงและความมั่นใจควบคู่ บนมือถือเลื่อนตารางภายในกรอบเพื่อดูคอลัมน์ที่เหลือ
5. กด `แสดงเพิ่ม` หากยังไม่เห็นคนที่ต้องการ ปุ่มเพิ่มผู้เล่นนำไปใช้ใน Squad Lab ไม่ใช่ซื้อเข้าทีม FPL

Ownership คือสัดส่วนการถือครองที่ข้อมูลเปิดเผย ไม่ใช่ effective ownership ที่รวมผลกัปตันในกลุ่มอันดับเฉพาะ และไม่ได้แปลว่าคนนั้นเหมาะกับทีมของคุณเสมอ

## 14. Squad Lab: ทดลองทีม 15 คน

เปิด [Squad Lab](https://sarayutp.github.io/fpl-decision-lab/#squad-lab) ใช้ทดลององค์ประกอบทีม ไม่ใช่โอนย้ายตัวจริง

1. กด `เริ่มจากทีมจริง` หรือ `ใช้ทีม FPL ล่าสุด` เมื่อปุ่มปรากฏ
2. ทดลองเอาคนออกและเพิ่มจาก Players ตรวจจำนวนตำแหน่ง งบ และคนต่อสโมสร
3. อ่าน `โอกาสอัปเกรด` เป็นทางเลือกเปลี่ยนคนตำแหน่งเดียวในงบ ไม่ใช่คำแนะนำให้ย้ายหลายคนทันที
4. กด `ส่งออก JSON` เก็บรายชื่อทดลอง หรือ `ล้างทีม` เพื่อเริ่มใหม่เฉพาะใน Lab

ทีมเต็มคือ GKP 2, DEF 5, MID 5, FWD 3 รวม 15 คน ไม่เกิน 3 คนต่อสโมสร ระบบป้องกันเพิ่มคนเกินเงื่อนไข งบ Lab ใช้ค่าสูงสุดระหว่าง 100.0m กับมูลค่าทีมล่าสุดจาก FPL

งบยังประมาณจากข้อมูลสาธารณะ ไม่ใช่งบขายจริง Lab ไม่คิดแผน hit แบบ Transfer Advisor และไม่ได้เปลี่ยนทีมฐานของ This Gameweek หรือ Planner อัตโนมัติ ถ้าจะใช้ทีมทดลองจริง ต้องตรวจการย้ายและราคาขายใน FPL ใหม่

## 15. AI Briefing: ส่งข้อมูลให้ ChatGPT ตรวจข่าว

เปิด [AI Briefing](https://sarayutp.github.io/fpl-decision-lab/#ai-briefing)

1. ตรวจ Team ID เวลาข้อมูลและ GW ให้ตรง
2. กด `คัดลอกสำหรับ ChatGPT` แล้ววางในแชตของคุณ
3. ขอให้ตรวจข่าวบาดเจ็บ แถลงข่าว โอกาสตัวจริง และเลื่อนโปรแกรมล่าสุด พร้อมลิงก์และเวลา แยกข้อเท็จจริงจากข้อสันนิษฐาน
4. นำหลักฐานใหม่ที่เชื่อถือได้กลับมาใส่ News & Risk และตรวจผลคำนวณใหม่
5. ตรวจเองก่อนทำรายการจริง คำตอบ AI อาจผิดหรือใช้ข่าวเก่าได้

ปุ่มคัดลอกประกอบบริบท Browser ปัจจุบัน รวมข้อมูลที่กรอกสำหรับวิเคราะห์ ส่วน Markdown ที่ดาวน์โหลดใน AI Briefing มาจาก snapshot ที่เผยแพร่ อาจไม่มีการปรับล่าสุดใน Browser อย่าคิดว่าสองอย่างนี้เหมือนกันทั้งหมด

อ่านเนื้อหาก่อนส่งให้บริการภายนอก เพราะมีรายละเอียดทีมและแผน เว็บไม่ได้เรียก OpenAI API และไม่ต้องกรอก API key คุณเลือกเครื่องมือ AI และส่งข้อมูลเอง

หาก Briefing ขาด ระบบปิดคัดลอก/ดาวน์โหลด ถ้าทีมหรือเวลาไม่ตรงข้อมูลหลัก จะหยุดคำแนะนำ ให้แก้ชุดข้อมูลก่อน ไม่ควรฝืนใช้ไฟล์เก่า

## 16. ข้อมูลเก็บที่ไหน และปุ่มล้างลบอะไร

| ข้อมูล | ที่เก็บ / ขอบเขต | เมื่อกดล้าง |
| --- | --- | --- |
| Snapshot ทีมสาธารณะ โปรแกรม โมเดล | ไฟล์ที่ผู้ดูแลเผยแพร่ | ไม่เปลี่ยนตามปุ่มล้างแผนใน Browser |
| FT เงิน ราคาขาย | Browser ของทีม | `ล้างข้อมูล Transfer` ล้างค่าที่กรอกส่วนนี้ |
| ข่าวเพิ่มเอง | Browser แยกทีม/ฤดูกาล | `ล้างทั้งหมด` ใน News & Risk ล้างข่าวเพิ่มเอง |
| Planner | Browser ตามบริบทแผน | `ล้างแผนใน Browser` ล้างแผนที่บันทึก |

รีเฟรชตามปกติไม่ลบแผน แต่ล้างข้อมูลเว็บไซต์ ใช้โหมดส่วนตัว เปลี่ยน Browser อุปกรณ์ หรือ origin/พอร์ต อาจทำให้ไม่เห็นข้อมูลเดิม **ไม่มี sync และยังไม่มีนำ JSON กลับเข้าเว็บ** ส่งออกเพื่อเก็บหลักฐานไว้อ่าน ไม่รับรองว่ากู้คืนอัตโนมัติได้

Snapshot ออนไลน์มีข้อมูลที่ FPL เปิดสาธารณะ เช่นชื่อทีม ผู้จัดการ Team ID และ picks หลัง deadline ไม่ควรเพิ่ม password, cookie, API key หรือข้อมูลส่วนตัวลง repository/ไฟล์สาธารณะ

## 17. ลำดับใช้งานประจำ Gameweek

### หลายวันก่อน deadline

ตรวจทีมและความสด อ่านโปรแกรมหลาย GW เติม FT/ราคาแล้วเทียบ Roll กับย้ายตัว ดู Planner เพื่อไม่ใช้ชิปเพราะคะแนน GW เดียวสูง หากยังมีเกมกลางสัปดาห์ เผื่อความเสี่ยงจากข่าวที่จะเปลี่ยน

### ภายใน 24 ชั่วโมงก่อน deadline

ตรวจข่าวต้นทางและเวลา ใช้ AI Briefing ช่วยรวบรวมได้แต่ตรวจแหล่งอ้างอิงเอง นำข่าวเข้า News & Risk เก็บ A/B ใหม่เมื่อบริบทเปลี่ยน ตรวจงบจริงและเหตุผลที่ hit จะคุ้มในช่วงที่เลือก

### ก่อน deadline โดยเผื่อเวลาสำรอง

1. ตรวจใน FPL ว่าทีมหลังย้ายตรงกับแผน
2. ตรวจ XI, C, VC, สำรอง และชิป รวมถึงสถานะบันทึกสำเร็จ
3. บันทึกเหตุผลในประวัติการตัดสินใจก่อน deadline หากต้องการทบทวน
4. อย่ารอวินาทีสุดท้าย เว็บหรือเครือข่ายอาจช้า

### หลังจบ GW

กรอกคะแนนจริงสุทธิใน Journal ระบุว่าตรงแผนหรือไม่ ทบทวนคุณภาพเหตุผล ข่าวและความเสี่ยง ไม่ตัดสินทุกอย่างจากคะแนนสัปดาห์เดียว

## 18. ตัวอย่างเดินตามทั้งกระบวนการ

ต่อไปนี้เป็น **ข้อมูลสมมติทั้งหมด** ไม่ใช่ราคาหรือคำแนะนำ GW ปัจจุบัน

สมมติมี 1 FT เงินในธนาคาร 0.5m ขาย A ที่ราคาขายจริง 5.0m ซื้อ B ราคา 5.4m เงินคงเหลือควรเป็น `0.5 + 5.0 − 5.4 = 0.1m`

1. ตรวจว่า A ยังอยู่ใน public picks ที่เว็บใช้ และทีมจริงของคุณ
2. กรอก FT = 1, bank = 0.5 ราคาขาย A = 5.0 ใน Transfers ตรวจแผนว่าผ่านงบจริง
3. อ่านผลสุทธิ 1/3/5 GW กับ Roll และข่าว B หาก A → B ไม่อยู่ในเส้นทาง Planner รุ่นนี้ไม่ได้รองรับพิมพ์ moves อิสระทุกแบบผ่าน A/B
4. ทดลองทางเลือกที่ระบบรองรับ เก็บ A เป็น “เก็บชิป” และ B เป็น “ใช้ชิปตามฉบับร่าง”
5. สมมติ A ได้สุทธิ 50 และ B ได้ 57 ใน GW นี้ +7 ยังไม่บอกว่าควรใช้ชิป เพราะไม่รวมประโยชน์ของการเก็บชิปในอนาคต
6. อ่านความเสี่ยงและข่าว หากข้อมูลเปลี่ยนให้เก็บทั้งคู่ใหม่ เลือกแผนสุดท้ายใน Planner แล้วตรวจและยืนยันใน FPL
7. บันทึกเหตุผลใน Journal ถ้าจะถามเพื่อนให้สร้างการ์ด ตรวจตัวอย่าง และส่งเอง

ผู้ดูแลที่มีสิทธิ์เปิด [GitHub Actions: Deploy Pages](https://github.com/Sarayutp/fpl-decision-lab/actions/workflows/deploy-pages.yml) เลือก `Run workflow` รอ build และ deploy สำเร็จก่อนรีเฟรช ผู้ใช้ทั่วไปไม่ต้องเปิดเครื่องหรือ Terminal เพื่อให้เว็บออนไลน์ทำงาน

## 21. สิ่งที่ระบบยังไม่ทำ

ยังไม่อ่าน private My Team แบบเรียลไทม์ ไม่เปลี่ยนทีมด้วย Team ID ช่องเดียว ไม่ซื้อขายหรือกดชิปจริง ไม่มีโพสต์การ์ดอัตโนมัติ และไม่ยืนยันความจริงของข่าวจาก URL ที่กรอกโดยอัตโนมัติ

ยังไม่มี sync ข้ามอุปกรณ์ นำ JSON กลับเข้าเว็บ เปรียบเทียบ moves อิสระทุกแบบใน A/B, effective ownership เฉพาะกลุ่มอันดับ, watchlist หรือแจ้งเตือนข่าวส่วนตัว และไม่รับรองความแม่นยำหรือคะแนนที่เพิ่มจากโมเดล

ใช้ข้อจำกัดเหล่านี้ประกอบการตัดสินใจ อย่าอาศัยชื่อปุ่มหรือไฟล์ export เพื่อสมมติว่าระบบทำสิ่งนั้นแล้ว

## 22. ดาวน์โหลด พิมพ์ และข้อมูลสำหรับผู้พัฒนา

### เก็บคู่มือไว้อ่าน

ด้านบนหน้าวิธีใช้งาน กด `ดาวน์โหลดคู่มือฉบับเต็ม` เก็บไฟล์ `.md` เปิดด้วยโปรแกรมอ่านข้อความหรือ Markdown ได้ เนื้อหาเหมือนบนเว็บ ไม่มีข้อมูลทีมส่วนตัวจาก Browser

กด `พิมพ์ / บันทึกเป็น PDF` เพื่อเปิดหน้าพิมพ์ แล้วเลือกบันทึกเป็น PDF หากอุปกรณ์รองรับ ตรวจตัวอย่างก่อน โดยเฉพาะการแบ่งหน้าตาราง ไม่มีอัปโหลดไปบริการแปลงไฟล์ ถ้าปิด JavaScript ใช้คำสั่งพิมพ์ของ Browser โดยตรง

ใช้สารบัญข้ามหัวข้อ และ Ctrl+F / ⌘F หรือ “ค้นหาในหน้า” บนมือถือเพื่อค้นคำ เช่น “ราคาขาย”, “Bench Boost”, “ข้อมูลเก่า”

### สำหรับผู้พัฒนาเท่านั้น

ต้นฉบับเดียวคือ `dashboard/guide.md` build แปลงเป็น `guide.html` และคัดลอก Markdown ให้ดาวน์โหลด เมื่อแก้ฟีเจอร์ควรแก้คู่มือให้ตรงชื่อปุ่ม ขั้นตอน ข้อจำกัด และผลที่คาดหวังด้วย

บนเครื่องพัฒนาเดิมที่มี Python 3.11 ขึ้นไปและโครงการพร้อมใช้งาน เปิด local server ด้วย:

```bash
cd /Users/sarayutp/Project/10_FPL
./scripts/run_local.sh
```

เปิด URL ที่ Terminal แสดง กด Control+C ใน Terminal เมื่อต้องการหยุด อย่าดับเบิลคลิก HTML เพื่อใช้ Dashboard เพราะโหลด JSON ต้องผ่านเว็บเซิร์ฟเวอร์

ดึงข้อมูลใหม่ในเครื่อง:

```bash
./scripts/update_data.sh
```

หากแก้คู่มือหรือหน้าเว็บ และต้องการสร้างใหม่จากข้อมูลเดิมโดยไม่ดึง FPL ใหม่:

```bash
.venv/bin/python -m fpl_mvp build-site
```

build local ไม่เผยแพร่ขึ้นออนไลน์เอง ผู้ดูแลต้องทดสอบและ deploy ตามขั้นตอนโครงการ ส่วนผู้ใช้ทั่วไปเปิดเมนูวิธีใช้งานได้เลย ไม่ต้องรันคำสั่งใด
